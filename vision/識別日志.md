# 視覺識別調試日志

## 2026年8月20日—8月30日

### 項目概況

本階段工作主要圍繞智能救援項目的視覺識別部分展開，目標是使系統能夠通過攝像頭獲取場景圖像，對場景中的幾何目標進行識別，並進一步區分目標的**形狀與顏色**，為後續的目標定位、路徑規劃及救援動作提供視覺信息。

截至8月20日前，視覺識別所需的**訓練集已基本搭建完成**，目前主要識別對象為不同形狀、不同顏色的幾何體。現階段工作的重點已由數據集建立逐步轉向程序調試、識別效果驗證以及視覺識別結果與整車控制系統之間的接口銜接。

需要說明的是，目前視覺識別部分的主要程序代碼由調試人員借助 AI 輔助生成，部分程序的底層實現原理和算法細節仍在理解、梳理及驗證過程中。因此，本階段不僅是對程序功能進行調試，同時也在逐步建立對整套視覺識別程序結構、輸入輸出關係及核心處理流程的理解。

# 8月20日  視覺識別程序整理與環境確認

### 當日工作內容

8月20日主要進行視覺識別程序的整理、運行環境確認以及現有訓練集的檢查。

由於訓練集已經基本搭建完成，因此本日沒有將主要精力放在數據採集，而是開始檢查已有數據是否能夠支撐後續的形狀和顏色識別。對訓練數據進行初步整理，確認不同類別之間具有較明顯的區分度，同時檢查圖片質量、目標完整程度以及標註的一致性。

程序方面，開始對目前已有的視覺識別代碼進行整理。由於主要程序是此前由 AI 輔助編寫，因此首先對程序的整體結構進行閱讀，嘗試區分出圖像輸入、圖像處理、目標識別、結果輸出等不同功能模塊。

在嵌入式工程方面，當前工程環境可以確認為 STM32F407VETx 平台，工程使用 STM32CubeIDE 的 GCC 工具鏈進行構建，工程中同時配置了 Debug 和 Release 兩套構建方式。

### 當日主要問題

通過初步閱讀程序發現，現有代碼雖然具有較完整的功能框架，但程序的每一部分具體作用還沒有完全掌握。尤其是圖像處理和識別結果判定部分，需要進一步確認其判斷條件、參數來源以及輸出格式。

此外，視覺識別程序與主控程序之間的通信方式以及識別結果後續如何被小車控制程序使用，也需要在後續調試中逐步確認。

### 當日成果

1. 確認視覺識別訓練集已經搭建完成。
2. 確定本階段主要識別目標為不同形狀、不同顏色的幾何體。
3. 完成已有視覺識別程序的初步整理。
4. 確認嵌入式主控工程環境為 STM32F407VETx + STM32CubeIDE/GCC。
5. 初步建立視覺識別程序的功能分區，為後續調試做準備。

# 8月21日  形狀識別與顏色識別功能調試

### 當日工作內容

8月21日開始進入實際功能調試階段，重點驗證程序是否能夠從攝像頭獲取的圖像中正確識別不同幾何體。

本日主要從「形狀」和「顏色」兩個維度進行測試。

首先對不同形狀的幾何體進行單獨測試，在保持拍攝距離和背景條件相對穩定的情況下，逐一觀察程序對不同幾何目標的識別結果。測試過程中重點關注程序能否正確區分不同幾何形狀，以及同一形狀在不同顏色情況下是否仍能保持較穩定的識別結果。

在此基礎上進一步增加顏色測試，對不同顏色的同類幾何體進行識別。通過測試發現，視覺識別不能僅考慮目標形狀，還需要同時考慮目標的顏色信息，最終形成「形狀＋顏色」的目標描述方式。

程序調試過程中，也開始嘗試理解 AI 輔助生成的代碼。對程序中的主要變量、函數和判斷流程進行人工梳理，確認每一部分代碼在整個視覺識別流程中的作用。

### 調試情況

在測試過程中發現，視覺識別結果容易受到實際環境因素影響，例如：拍攝角度發生變化；目標與攝像頭距離變化；現場光照強度改變；背景顏色與目標顏色接近；多個幾何體同時出現在視野中等等。

因此，本日調試的重點不只是判斷「能不能識別」，還開始轉向判斷「在不同場景下能否保持穩定識別」。

### 當日成果

1. 完成不同幾何形狀的初步識別測試。
2. 完成不同顏色幾何體的初步識別測試。
3. 初步驗證「形狀＋顏色」雙重識別思路可行。
4. 開始梳理 AI 輔助生成程序的結構和功能。
5. 發現光照、背景和拍攝角度會直接影響識別效果，後續需要增加環境適應性測試。

# 8月22日  識別穩定性與程序參數調試

### 當日工作內容

8月22日主要進行視覺識別程序的細化調試，工作重點由「功能是否能實現」逐步轉向「識別是否穩定」。

在前一天測試基礎上，增加了不同位置、不同距離以及不同姿態下的幾何目標測試。通過反覆改變目標在畫面中的位置，觀察程序是否仍然能夠對目標進行正確分類。

同時對程序中的識別參數進行逐步調整。由於現有程序主要由 AI 輔助生成，因此調試過程採取「修改參數—運行測試—觀察結果—再次調整」的方式，逐漸確認不同參數對識別效果的影響。

本日還開始關注視覺識別結果的輸出方式。除了判斷目標屬於哪種形狀、哪種顏色之外，也需要確認識別結果能否以比較明確、規範的形式輸出，方便後續與主控程序進行數據交換。

### 程序理解方面

經過連續幾天的調試，開始對程序的基本處理流程形成比較清晰的認識，即：

**圖像獲取 → 圖像處理 → 目標提取 → 形狀判斷 → 顏色判斷 → 識別結果輸出**

目前對各部分底層算法的理解仍然不完全，但已經可以從功能層面理解程序的主要工作流程。

### 工程方面

STM32F407VETx 工程中使用 STM32CubeIDE 管理工程，編譯工具鏈為 MCU ARM GCC，Debug 工程啟用了 `DEBUG`、`USE_HAL_DRIVER` 和 `STM32F407xx` 等宏定義；Release 工程同樣針對 STM32F407VETx 配置。

此外，工程使用 `STM32F407VETX_FLASH.ld` 作為主要鏈接腳本，其 Flash 區域配置為 512 KB，RAM 配置為 128 KB，並額外配置 64 KB CCMRAM。

這些配置目前主要作為主控程序運行環境的一部分，並非視覺識別算法本身，但對後續將視覺識別結果接入整車控制程序具有支撐作用。

### 當日成果

1. 增加不同距離、不同位置下的視覺識別測試。
2. 開始對識別相關參數進行調試。
3. 初步分析識別結果不穩定的可能原因。
4. 梳理出完整的視覺識別基本流程。
5. 開始考慮識別結果與主控程序之間的接口問題。

# 8月23日  視覺識別功能階段性驗證

### 當日工作內容

8月23日主要進行目前視覺識別功能的階段性總結與整體測試。

本日對前幾天的調試內容進行集中驗證，將不同形狀、不同顏色的幾何目標重新組合進行測試，觀察程序在相對接近實際使用環境的條件下能否完成識別。

測試重點從單個目標逐漸轉向多種目標組合，觀察不同幾何體和不同顏色同時出現在畫面中時，程序能否保持基本的分類能力。

同時對前幾天修改過的程序參數進行整理，保留目前測試效果較好的配置，並記錄存在問題的場景，以便後續進一步優化。

### 階段性結果

經過8月20日至8月23日連續幾天的測試，目前視覺識別部分已基本形成可工作的功能框架：

**攝像頭獲取圖像 → 對場景中的幾何目標進行分析 → 判斷幾何體形狀 → 判斷幾何體顏色 → 輸出識別結果**

目前已具備識別不同形狀、不同顏色幾何體的基本能力，訓練集也已經完成搭建，因此視覺識別部分已由前期的數據準備逐步進入實際應用調試階段。

但從工程可靠性的角度來看，目前仍然不能將其視為完全成熟的視覺識別模塊。主要原因是：

一是部分算法代碼由 AI 輔助生成，目前調試人員對底層實現細節掌握還不夠深入；

二是現場光照、背景、距離和拍攝角度等因素仍可能造成識別結果波動；

三是目前主要驗證的是幾何體的分類功能，後續還需要進一步完善目標定位、連續幀穩定性以及視覺識別結果與小車運動控制之間的聯動。

### 當日成果

1. 完成現階段視覺識別程序的階段性驗證。
2. 基本確認不同形狀、不同顏色幾何體可以被識別。
3. 完成近期調試參數和測試結果整理。
4. 明確後續需要重點解決的問題。
5. 為下一階段「視覺識別＋運動控制」聯調提供基礎。

# 8月20日—8月23日階段總結

經過4天的持續調試，視覺識別部分已完成從**訓練集建立 → 程序整理 → 基礎功能驗證 → 參數調試 → 階段性測試**的過渡。

目前已基本實現對不同形狀、不同顏色幾何體的識別，說明現有訓練數據和視覺識別程序具備初步可用性。

本階段的一個重要特點是：現有識別程序並非完全由調試人員從底層自主編寫，而是在 AI 輔助下生成後，再由人工進行部署、修改和測試。因此目前工作的重點除了「讓程序運行起來」，還包括逐步理解程序結構和建立對識別算法的實際掌握能力。

從工程角度來看，目前主控部分採用 STM32F407VETx，工程使用 STM32CubeIDE 和 ARM GCC 工具鏈，已具備 Debug、Release 等基本工程配置。

下一階段工作的主要方向將包括：

1. 進一步理解現有視覺識別程序，明確每個核心函數和參數的實際作用；
2. 繼續增加不同光照、不同距離、不同背景下的測試；
3. 提高識別結果的穩定性和抗干擾能力；
4. 完善視覺識別結果的輸出格式；
5. 將視覺識別結果逐步與 STM32 主控及小車運動控制程序進行聯調；
6. 最終形成完整的「目標發現—目標識別—結果輸出—小車執行」流程。

截至2026年8月23日，視覺識別模塊已完成初步功能搭建並具備基本測試能力，當前階段的主要問題已由「功能是否能實現」轉變為「識別是否穩定」以及「程序是否真正被開發人員掌握」。因此後續工作將以**提高識別可靠性、完善程序理解和完成系統聯調**為主要目標。

# 8月24日 舵機性能調試

### 當日工作內容

8月24日主要進行了攝像頭和左、右機械臂舵機的調試，使之能夠自主轉動。

接線方面：三根红线→外部稳压5~6v电源正极；三根棕/黑线→外部电源负极；外部电源负极→同时连接STM32的GND，必须共地

### 工程方面

1. 不要用树莓派或STM32板载5V给三个舵机供电。建议外部电源至少5v/3A,最好5V/5A。
2. 接好后先不要打开舵机电源,回复我"接线完成"。随后我会先测试摄像头舵机在中位1500μs,再逐个测试两只机械臂舵机。

### 當日成果

1. 攝像頭、兩個機械臂都可以自主轉動。
2. 下一階段目標是讓攝像頭能夠根據識別內容轉動（追蹤救援物資）。
